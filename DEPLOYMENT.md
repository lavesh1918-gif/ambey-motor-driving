# Deployment Guide — Shree Ambhey Motor Driving

This project is a high-performance **React 19 + TypeScript + Vite + Tailwind CSS** web application designed for **Cloudflare Workers** (with Static Assets) and **Cloudflare Pages** (Git-based or Direct Upload).

---

## 1. Cloudflare Git-Based Deployment Configuration

When deploying from Git to Cloudflare (Workers or Pages), configure the build settings as follows:

| Setting | Value |
| :--- | :--- |
| **Framework preset** | `Vite` |
| **Build command** | `bun run build` |
| **Deploy command** | `npx wrangler deploy` |
| **Build output directory** | `dist` |
| **Root directory** | `/` |

> **Note on Bun Version Compatibility:**
> The repository includes a `bun.lock` file fully compatible with Cloudflare's build environment (Bun 1.2.15+) as well as modern Bun releases (1.4+). Both `bun install --frozen-lockfile` and `bun run build` execute cleanly with zero errors.

---

## 2. Why Did the Earlier Errors Occur?

### Error A: "Unknown lockfile version / lockfile had changes, but lockfile is frozen"
- **Cause:** Cloudflare's build environment runs Bun 1.2.15 by default. The repository previously had a lockfile generated by a different version of Bun (`lockfileVersion: 2`). Bun 1.2.15 could not parse version 2 and failed when attempting to enforce a frozen lockfile.
- **Resolution:** `bun.lock` has been cleanly regenerated to match the lockfile schema supported by Bun 1.2.15 (`lockfileVersion: 1`), while remaining forward-compatible with newer Bun versions.

### Error B: "This uploader does not yet support projects that require a build process. TypeScript files were found."
- **Cause:** Cloudflare's direct web dashboard uploader only accepts compiled static web assets (`dist/`), not uncompiled TypeScript source files.
- **Resolution:** Use `npx wrangler deploy` for Workers or configure Git-based Pages deployment with `bun run build` pointing to the `dist` directory.

## 3. Deployment Methods

### Option A: Cloudflare Workers via Wrangler CLI (Recommended)
The project includes `wrangler.jsonc` and `wrangler.toml` configured for Cloudflare Workers Static Assets:
```bash
# 1. Install dependencies
bun install

# 2. Build production assets
bun run build

# 3. Deploy
npx wrangler deploy
```

### Option B: Cloudflare Pages Git-Based Deployment
1. Connect your Git repository in Cloudflare Dashboard → **Compute (Workers) / Pages** → **Create application** → **Pages** → **Connect to Git**.
2. Select your repository and branch.
3. Configure build settings:
   - **Build command:** `bun run build`
   - **Build output directory:** `dist`
   - **Root directory:** `/`
4. Click **Save and Deploy**. Cloudflare will automatically build and deploy on every push. Single-page application routing is natively handled by Cloudflare Static Assets (`not_found_handling = "single-page-application"`).

### Option C: Cloudflare Pages Manual Upload (Drag & Drop)
If deploying via drag-and-drop on the Cloudflare dashboard:
1. Run `bun run build` locally.
2. Locate the `./dist` folder.
3. Upload the **contents of `./dist`** (never upload the project root or source directory).
